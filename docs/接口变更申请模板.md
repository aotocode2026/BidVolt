# 接口变更申请模板

> **提交位置**：Discussions → Ideas 分类（本仓库已停用 Issue）。
> **写作纪律**：只写现状、期望目标、为什么现有接口不够、业务必要性与约束；
> **不写**技术方案指定（"用 xxx 实现"）、**不写**命令式要求（"必须…""应该…""你去…"）——
> 方案由维护方设计，先入为主的方案与命令会误导设计方向。
> **评估口径**：①现有接口是否已能实现（能则前端自己实现，驳回）；
> ②是否属纯前端职责（是则前端自己实现，驳回）；
> ③新增/修改是否影响现有流程、语义与其他调用方（影响流程的变更须给出充分业务理由，
> 后端不会为前端便利付出影响流程的代价）。

复制下面六节填写后发布：

---

## 1. 现状
（现在用哪个/哪些接口；接口路径 + 现在能拿到的字段 + 缺哪个数据/能力）

## 2. 期望目标
（希望前端最终能做什么功能/展示什么——用「希望…」表述）

## 3. 为什么现有接口不够
（逐条说明：已尝试的现有接口 + 各自缺什么；能用现有数据在前端加工实现的，
请先在前端实现，不属于本申请范围）

## 4. 业务必要性
（不做这个功能的业务影响：影响什么场景/什么用户/什么验收项）

## 5. 约束
（不能破坏的现有行为：其他调用方/旧页面兼容、字段语义兼容、错误约定等）

## 6. 建议的接口形状（可选，仅供参考）
（路径/方法/入参/出参草稿；维护方会重新设计，不保证照此实现）
