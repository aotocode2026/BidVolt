# BidVolt 前端对接接口文档（Demo 控制台 · Agent 主会话新方案）

> 适用版本：2026-08-31 当前线上。基址示例：`http://47.100.182.3:28123`。
> 所有接口路径带 `/api/v1` 前缀；鉴权方式统一为 `Authorization: Bearer <access_token>`。
> 参考实现（页面同款调用）：`app/static/agent-demo.html`。

---

## 0. 通用约定

### 0.1 鉴权与令牌

| 令牌 | 有效期 | 用途 |
|---|---|---|
| `access_token` | 2 小时 | 每次请求携带（Bearer） |
| `refresh_token` | 30 天 | 仅用于 `/auth/refresh` 换取新令牌对，**换新后旧 refresh 立即作废（轮换）** |

**401 自动续期约定（前端必须实现）**：任意接口返回 401 时，
用本地存的 `refresh_token` 调 `POST /auth/refresh` 换新令牌对并**重试原请求一次**；
续期也失败才提示用户重新登录。页面对应实现见 `agent-demo.html` 的 `api()`。

### 0.2 错误约定

- 失败返回 `{"detail": "原因"}`，HTTP 状态码表达类别：401 未登录/令牌失效、
  403 无权限、404 不存在、409 状态冲突（如任务终态不可对话、未打包）、422 参数错误。
- 前端应把 `detail` 原文展示给用户（服务端保证原因具体可读）。

### 0.3 任务状态码

`1` 排队中 / `2` 运行中 / `3` 完成 / `4` 失败可重试 / `5` 已取消 / `6` 失败终态。
Agent 主会话任务的 `result.outcome`：`complete`（全部验收门通过）/ `incomplete`（主会话如实判定未闭环，`result.reason` 给原因）。

## 1. 账号

### POST /api/v1/auth/register
```json
{"email":"a@b.com","password":"Abc123","enterprise_name":"XX公司"}
```
→ `201`：`{"user_id":1,"enterprise_id":2,"access_token":"...","refresh_token":"..."}`（注册即登录）。

### POST /api/v1/auth/login
```json
{"email":"a@b.com","password":"Abc123"}
```
→ `200`：同上 TokenPair。

### POST /api/v1/auth/refresh
```json
{"refresh_token":"..."}
```
→ `200`：新 TokenPair（旧 refresh 作废）。

### GET /api/v1/auth/me
→ `200`：`{"user_id":1,"email":"a@b.com","enterprise_id":2,"enterprise_name":"XX公司",...}`
用途：页面顶部「登录状态条」展示。

## 3. 文件与项目材料

### POST /api/v1/files/upload（multipart/form-data）
字段：`target` = `project`（项目材料）或 `enterprise`（企业资料）；
`project_id`（target=project 必填）；`files` = 一个或多个文件（**支持多选**）。

→ `200`：`{"files":[ {...} ]}`，单文件条目字段：
```json
{
  "file_id": 1799,
  "name": "xxx.docx",
  "size": 12345,
  "status": 3,
  "parse_status": null,
  "duplicate": true,          // 内容与库内相同（sha256 去重），file_id 指向既有文件
  "asset_id": 12,             // 仅 target=enterprise
  "auto_ingest": true,        // 仅 target=enterprise：自动入库分类+初始事实
  "facts_extracted": 5,
  "expanded": {               // 上传的是 zip：自动解包入库结果
    "imported": 3, "duplicates": 1, "failed": 0
  },
  "error": "原因"              // 该文件失败（其余文件不受影响）
}
```
要点：
- 压缩包**上传即自动解包入库**（内部文件成为项目材料/企业资产，原件保留）；嵌套 zip 递归展开（≤6 层）；
  `expanded.failed` 条目带包内路径与原因。
- 解析失败的文件会整体拒绝（`error` 给原因），不会留下"上传成功但用不了"的记录。

### GET /api/v1/files/projects/{project_id}/materials
→ `200`：材料数组，条目字段（**前端列表与信号展示全量口径**）：
```json
{
  "material_id": 321, "file_id": 1799,
  "file_name": "合同专用条款其他文件.docx", "ext": ".docx",
  "status": 2, "parse_status": null,
  "block_count": 152,                       // 可提取文字块数（0=无文字层，多为扫描件/压缩包）
  "block_stats": {"paragraph": 120, "table": 31, "image": 1},  // 块类型统计
  "media_count": 219,                       // 文件内嵌图片张数（解析层信号）
  "image_count": 219, "image_described_count": 219,            // 图片描述进度（入库后台任务）
  "source_archive_id": 1798,
  "source_archive_name": "合同专用条款文件.zip",   // 解包来源压缩包名
  "archive_path": "合同专用条款其他文件.docx",     // 包内相对路径（保留层次）
  "expanded_count": 2                        // 仅 zip 行：该包已解包展开的文件数（0=未解包）
}
```

### GET /api/v1/files/{file_id}/blocks?page=1&size=100
→ `200`：`{"items":[{"block_id":1,"block_type":"paragraph|table|header_footer|image","page_no":null,"block_index":0,"text":"...","extra":{}}],"total":1032,"page":1,"size":100}`
注意：索引是导航信号，**内容以原件为准**（前端提示语可沿用此口径）。

### GET /api/v1/files/{file_id}/download
→ 文件流（`Content-Disposition` 带原始文件名）。

### POST /api/v1/files/archive（存量压缩包补解包）
```json
{"archive_file_id": 1798, "target": "project", "project_id": 193}
```
→ `200`：`{"job_id":1,"status":2,"result":{"imported":[1800,...],"failed":[{"name":"路径","reason":"原因"}],"duplicates":[{"name":"路径","file_id":99}]}}`
页面「解包入库」按钮调此接口；`status`：1 处理中 / 2 全部成功 / 3 部分失败。

### GET /api/v1/files/image-describe-progress（后台识图进度）
→ `200`：`{"queued":0,"running":0,"done":1368,"failed_terminal":0,"remaining":0,"described_images":1944}`
页面顶部进度条 30 秒轮询此接口；`remaining==0` 且 `done+failed_terminal>0` 时显示"全部完成"。

### GET /api/v1/files/{file_id}/image-descriptions（图片结构化描述清单）
→ `200`：
```json
{"file_id":1799,"image_count":47,"described_count":47,
 "items":[{"ordinal":0,"page":null,"sha256":"d76b...","described":true,
           "description":{"doc_type":"发票","subject":"...","numbers":["..."],"dates":["..."],"amounts":["..."],"people":["..."],"stamps":["..."],"text_summary":"...","is_scan":true}}]}
```
用途：写作阶段「找证据」（描述找图）；装订关键字段仍需 vision 复核原件图。

## 4. Agent 主会话任务（端到端投标流程）

### POST /api/v1/projects/{project_id}/agent-run
```json
{"idempotency_key":"agent-<唯一串>","payload":{},"resume_from_task_id":1772}
```
- `idempotency_key` 必填（重复提交返回同一任务，`created=false`）。
- `resume_from_task_id`：沿用上一任务的会话继续跑（上一任务须有 `result.session_id`）。
→ `201`：
```json
{"task_id":1773,"status":1,"created":true,"resume_session_id":"20260830_...","progress":{...},"capability_token":"..."}
```

### GET /api/v1/projects/{project_id}/agent-run/{task_id}
→ `200`：
```json
{"task_id":1773,"task_type":"agent_pipeline","status":2,
 "progress":{"phase":"agent_pipeline","status":"running","percent":15,"current_work":"提问关已发起（0/1 组已答）…"},
 "result":{"outcome":"complete","reason":null,"session_id":"...","action_list":["盖章：..."],"customer_asks":[...]},
 "error":null,"customer":{"asks":[...],"action_list":[...]}}
```
- `progress.percent/current_work` 由真实里程碑驱动（5 启动 → 15 提问关 → 40-70 成文 → 85 打包 → 100 完成），页面 8 秒轮询。
- 终态（status∈{3,4,5,6}）按 `result.outcome` 渲染完成/未闭环/失败横幅。

### GET /api/v1/projects/{project_id}/agent-run/{task_id}/stream?since=N（SSE）
事件流（回放 + 实时，控制台数据源）：
```
event: message
data: {"seq":101,"kind":"hermes|service|user|tool|error","content":"..."}

event: end
data: {"status":3,"session_id":"...","outcome":"complete","reason":null,"action_list":[...]}
```
- `since=N`：从 seq>N 补发；结束后发 `event: end`。
- 前端渲染建议：`kind` 着色区分（服务→主会话 / 主会话输出 / 客户→主会话 / 工具 / 错误）；
  控制台只渲染最近 N 条（如 2000），完整记录随交付包内 `会话记录/主会话记录.md`。

### GET /api/v1/projects/{project_id}/agent-run/{task_id}/questions（客户问卡）
→ `200`：
```json
{"asks":[{"ask_id":13,"kind":"question","items":[{"q":"...","need":"为什么需要","checked":"已自查"}],
          "answered":false,"answer":null,"created_at":"2026-08-30T07:21:55Z",
          "window_minutes":20,"timeout_notified":false}],
 "action_list":["盖章：授权委托书第X页加盖公章"]}
```
- **问答窗口**：每条提问有 `window_minutes`（默认 20）窗口；超时后服务端注入「由你自行决定」信号（`timeout_notified=true`），
  问卡**仍可补答**——补答会回传主会话回填重验。前端问卡须显示倒计时与「已超时（仍可补答）」状态。
- 多组提问全部展示（每组独立倒计时 + 独立提交）。

### POST /api/v1/projects/{project_id}/agent-run/{task_id}/asks/{ask_id}/answer
```json
{"answer":"1. …\n2. …"}          // 字符串整体一条；或 ["答1","答2"] 逐条对应
```
→ `200`：`{"ask_id":13,"answered":true,"queued":true,"reply":null}`
- 任务运行中：`queued=true`（排队注入，主会话忙完当前步骤处理）；
- 任务终态：走直接对话通道（`queued=false`，`reply` 为主会话回复）。

### POST /api/v1/projects/{project_id}/agent-run/{task_id}/chat（控制台对话）
```json
{"message":"...","mode":"queue"}   // mode: queue（默认，排队下一轮）| steer（插话，不打断，下一步工具调用后注入改方向）
```
→ `200`：
```json
{"queued":true,"mode":"queue","reply":null,"session_id":"...",
 "message":"消息已送达主会话：它正在忙手头这一步，做完马上读你的消息并回复（通常几分钟内，不用等整份标书完成）。回复见会话控制台。"}
```
- 运行中一律 `queued=true`（消息经泵循环注入长驻会话，不另起进程抢会话）；
- 终态任务：`queued=false`，`reply` 即回复。

### POST /api/v1/projects/{project_id}/pre-chat（任务前对话）
```json
{"message":"现在都有哪些资料？"}
```
→ `200`：`{"reply":"项目共 5 份材料…","session_id":"2026...","returncode":0}`
- 会话 id 存项目；之后点【开始】发起 agent-run 时，任务书自动注入该会话（交代成为主会话上下文）。
- 该阶段模型持**只读**业务工具（列材料/查资料库/查需求），能据实回答"有什么资料"。

### GET /api/v1/projects/{project_id}/response-package
→ 响应文件包 zip（价格 3 + 商务 4 + 技术 2 + 内部管理 1 + 会话记录 2 + manifest.json）。
未打包时 409（detail 指引）；任务完成后由「下载响应文件包」按钮调用。

## 5. 企业资料

### GET /api/v1/enterprise/assets
→ `200`：`[{"asset_id":1,"name":"...","asset_type":"业绩","category_id":2,"status":2,"source_file_id":99,"image_described":true}]`
`image_described`：该图片资料是否已有结构化描述（入库后台任务产出）。

→ `200`：上述字段 + `facts:[{"fact_id","fact_key","fact_value","confidence","status"}]`
+ `image_description:{doc_type,subject,numbers,dates,amounts,people,stamps,text_summary,is_scan}`（图片资产且已描述时非空）。

## 7. 页面状态约定（Demo 页 localStorage，前端复刻可参考）

| Key | 含义 |
|---|---|
| `bidvolt_agent_token` / `bidvolt_agent_refresh` | 令牌对 |
| `bidvolt_agent_pid` / `bidvolt_agent_pname` | 当前项目 id/名 |
| `bidvolt_agent_task` / `bidvolt_agent_last_task` | 当前任务 / 上一任务（续跑按钮用） |
| `bidvolt_agent_email` | 登录邮箱（回填） |

页面顶部三行固定 UI：登录状态条（`/auth/me` 驱动）→ 后台识图进度条（30s 轮询）→ 操作区。
