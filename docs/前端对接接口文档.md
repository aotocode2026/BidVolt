# BidVolt 前端对接接口文档

> 适用版本：2026-09-07 当前线上。
> 基址示例：`http://47.100.182.3:28123`。
> 所有接口路径带 `/api/v1` 前缀；鉴权方式统一为 `Authorization: Bearer <access_token>`。

---

## 0. 通用约定

### 0.0 本文档的内容和结构

本文档用于说明 BidVolt 前端对接所需的后端 HTTP 接口，结构如下：

1. `所有接口名单列表`：按模块列出全部接口路径和方法，便于快速查找。
2. `所有接口详细介绍`：按模块逐条说明接口路径、处理函数和主要用途。

### 0.1 鉴权与令牌

| 令牌 | 有效期 | 用途 |
|---|---|---|
| `access_token` | 2 小时 | 每次请求携带（Bearer） |
| `refresh_token` | 30 天 | 仅用于 `/auth/refresh` 换取新令牌对，换新后旧 refresh 立即作废 |

任意接口返回 401 时，前端应使用本地 `refresh_token` 调用 `POST /auth/refresh`，并用新令牌重试原请求一次；仍失败则提示重新登录。

### 0.2 错误约定

- 失败通常返回 `{"detail": "原因"}`。
- 状态码表达类别：401 未登录/令牌失效、403 无权限、404 不存在、409 状态冲突、422 参数错误。
- 前端应直接展示 `detail` 原文，服务端保证原因具体可读。

### 0.3 任务状态码

`1` 排队中 / `2` 运行中 / `3` 完成 / `4` 失败可重试 / `5` 已取消 / `6` 失败终态。

Agent 主会话任务的 `result.outcome`：

- `complete`：全部验收门通过
- `incomplete`：主会话判定未闭环，`result.reason` 给出原因

### 0.4 相关文档位置和作用

- **《接口更新记录》**：`docs/接口更新记录.md`
  - 记录接口的新增、修改、废弃等历史变化。
  - 按时间倒序或正序排列，包含更新时间、更新原因、关联 commit/issue/discussion 和注意事项。

- **《接口变更申请模板》**：`docs/接口变更申请模板.md`
  - 用于提交接口变更申请。
  - 需要新增或修改接口时，先按该模板说明现状、目标、必要性和约束。
