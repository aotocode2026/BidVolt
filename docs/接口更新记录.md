# 接口更新记录

本文档记录 BidVolt 接口的新增、修改和废弃情况，便于追溯接口变化历史。

## 2026-09-07

- **产物详情文件健康信号**
  - `GET /projects/{project_id}/assembly/artifacts/{artifact_id}/inspect` 响应新增 `file_health`
    （`bytes/mime/kind/readable/zip_ok/document_xml_ok/text_chars/sheets/entries/error`）
  - 文件损坏时返回 `readable=false` 与原因，不再抛 500
  - 核验结论：项目 207 artifact 938（编制逻辑与评分响应记录.docx）文件有效，预览失败属前端预览层
  - 关联 commit：`5fa1061`
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/24

- **上传批次 ZIP 子文件关联与逐文件解析状态**
  - `GET /files/batches/{batch_id}` items 新增 `source_archive_file_id`（来源压缩包）、
    `archive_path`（包内相对路径）、`parse_status`（parsing/done/failed，按当前文件状态实时回读）
  - 上传 zip 自动解包后：每个成功子文件/失败项/重复项各写一条批次条目，失败项带可读原因
  - `upload_batch_item` 增加 3 个字段（迁移 `0032`）
  - 关联 commit：`362fae4`
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/23

- **评分与报价绑定正式 artifact 版本**
  - `GET /projects/{project_id}/scores` 新增 `has_score`、`artifact_versions`、`scored_artifacts`；
    `stale_reasons` 修复字符串/整数键比对（此前版本变化永远不会判过期），并新增 artifact 维度过期原因
  - `evaluate` / `re-evaluate` 冻结 `artifact_versions`（`artifact_id -> version_no`）入快照与 `score_record`
  - `POST /quotes/calculate`、`POST /quotes/apply` 请求新增可选 `artifact_id` / `artifact_version_no`；
    `GET /quotes/{calc_id}` 与 `GET /quotes` 列表返回这两个绑定字段
  - 迁移 `0031`：`score_record.artifact_versions` + `quote_calc.artifact_id/artifact_version_no`
  - 关联 commit：`1084841`
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/22

- **正式文件逻辑版本链与覆盖历史**
  - `POST /projects/{project_id}/assembly/artifacts/{artifact_id}/save`：
    - `mode=new` 响应新增 `logical_file_id`/`logical_version_no`/`parent_artifact_id`（继承逻辑身份，旧版保留）
    - `mode=overwrite` 覆盖前归档当前内容（`agent_artifact_content_version` 表），响应新增逻辑版本字段
  - 新增 `GET /projects/{project_id}/assembly/artifacts/{artifact_id}/versions`（同一逻辑文件版本链）
  - 新增 `GET /projects/{project_id}/agent-artifact/{artifact_id}/versions/{version_no}/download`（历史版本下载）
  - 产物清单/详情响应新增 `logical_file_id`/`logical_version_no`/`parent_artifact_id`
  - 下载响应头改用 RFC 5987 `filename*`（中文文件名不再触发 latin-1 编码错误）
  - 关联 commit：`aae2676`
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/21

- **长历史补读与 pre_chat 持久化**
  - `GET /projects/{project_id}/agent-run/{task_id}/stream`：终态任务按 `seq` 游标补读至空才发 `end`，长历史不漏尾部消息；`end` 事件新增 `last_seq`
  - 新增 `GET /projects/{project_id}/pre-chat/messages?since=&limit=`（任务前对话历史，游标增量/补读）
  - `POST /projects/{project_id}/pre-chat`：请求新增可选 `client_message_id`（≤100 字符，幂等）；响应新增 `message_id`/`reply_to_message_id`（不再用随机 UUID）/`status`（processed/failed/no_valid_reply）/`error`/`duplicate`
  - 新增表 `pre_chat_message`（迁移 `0029`，含 RLS），user/hermes/error 事件落库可恢复
  - 关联 commit：`819796d`
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/20

- **聊天消息关联、幂等与异常处理**
  - `POST /projects/{project_id}/agent-run/{task_id}/chat`：
    - 请求新增可选 `client_message_id`（≤100 字符，客户端幂等标识；超长返回 422）
    - 响应新增 `status`（`queued` / `processing` / `processed` / `failed` / `no_valid_reply`）、`error`、`duplicate`
    - `message_id` = 本条用户消息的 seq，`reply_to_message_id` = 对应回复事件的 seq（成功时二者不再同值）
  - 回复输出统一清洗：剥离 Reasoning 框、会话尾注、框线与状态条噪音；Hermes 退出码非 0 或输出无有效内容时返回 `failed` / `no_valid_reply`
  - `deploy/install-hermes.sh` 默认 `display.show_reasoning=false`，从源头关闭 Reasoning 复盘框
  - 关联 commit：`1bc8da0`（行尾规范化 `731e26e`）
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/19

- **企业资产分类确认与人工修改**
  - 新增 `POST /enterprise/assets/{asset_id}/confirm-category`
  - 完善 `PATCH /enterprise/assets/{asset_id}/category`
  - 更新前端 `app/static/app.js`，增加“确认分类”和“改分类”操作
  - 人工修改分类后，`category_id`、`asset_type` 会同步更新，状态置为已确认
  - 关联 commit：`26265d5`
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/18

- **AI 企业资产分类**
  - 新增 `app/services/asset_classification_service.py`
  - 修改 `POST /enterprise/ingest` 和 `POST /enterprise/assets/{asset_id}/classify`
  - 分类逻辑：图片复用 qwen-vl 描述，文档使用 MiniMax 文本模型，其他文件回退文件名规则
  - 关联 commit：`dbbb030`
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/18
