# 接口更新记录

本文档记录 BidVolt 接口的新增、修改和废弃情况，便于追溯接口变化历史。

## 2026-09-13（打包号冲突门禁去掉语料级误判）

- **`POST /projects/{project_id}/assembly/package` 号冲突门禁口径修正（issue #68）**
  - 原口径：收集全库 `image_description.numbers_conflict` 的**全部**值，交付件正文命中即拒绝。
    实测会把语料级正确值拦死——`91110111318157964Q` 在 `numbers_verified` 出现 236 次、
    在 `numbers_conflict` 仅 1 次（某图第二轮给出形近变体时把正确值也写进了候选）。
  - 新口径：硬门禁集合 = `{conflict 值} - {全库 verified 值}`，只拦**从未被任何图确认过**的候选
    （如 `C1601J0253904821`：conflict×4 / verified×0，仍拒绝打包）。
  - 新增审计信号 `audit.numbers_conflict_confirmed`：交付件命中的"已确认但仍有冲突记录"的值，
    文件级明细，只提示不拦截，供验收/评审子 agent 核对。
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/68

## 2026-09-12（成文通道混合式：append 图片节点）

- **`POST /projects/{project_id}/assembly/slices/{slice_id}/append` 支持图片节点（issue #67）**
  - `nodes[]` 新增 `{"type":"image", ...}`，两种来源（二选一）：
    - `{"type":"image","file_id":<企业资料库原件 file_id>,"page":<PDF 页码，可选>,
       "width_cm":15,"caption":"图：…"}`——PDF 取指定页（150dpi 渲染 PNG），图片按原格式直用；
    - `{"type":"image","path":"/tmp/xxx.jpg","width_cm":15,"caption":"图：…"}`——服务器本地
      路径，仅允许 `/tmp/`、`/data/hermes/` 与系统临时目录。
  - 服务端按宽 ≤16cm、高 ≤23.2cm 等比缩放居中插入；题注楷体 10.5 居中且**不写大纲级别**；
    缺来源 / 路径越界 / 文件不存在 / 单张超过 12MB 一律返回 409。
  - 新增 `page_break: bool`（默认 true；逐条目标题 append 时传 false）。
  - 回执新增 `appended_images`（本次追加图片数）与 `images_resolved`（解析成功数）。
- **打包审计新增骨架覆盖信号（issue #67，只提示不拦截）**
  - `POST /projects/{project_id}/assembly/package` 的回执/manifest 的 `audit` 新增
    `skeleton_scan`：`{文件名: {draft_item, draft_top_items, missing}}`，对照底稿该条目的
    顶层条目名报出成品中未出现的条目，供验收/评审子 agent 核对。
  - 与 issue #65/#66 的两条硬门禁（缺页码、大纲噪声）不同，骨架覆盖**不做硬判**：
    交付件常用"章节号"体系，与底稿"条目标号"不同体系，按名称硬判会误杀。
    该信号本身是**启发式**的（只以底稿「（X）条目」行做锚点；条目标题在底稿里只以正文列表行
    出现时不给信号，避免"12 项全缺"这类假缺失），仅供人工/验收子 agent 参考。
- 关联 issue：https://github.com/aotocode2026/BidVolt/issues/67

## 2026-09-12（交付 docx 页码与大纲规范化）

- **交付 docx 归一化 + 打包门禁（issue #65 / #66）**
  - 以下接口在写入 docx 产物前会做服务端归一化（**回执新增 `normalize` 计数对象**）：
    `POST /projects/{project_id}/assembly/upload-file`、
    `PUT /projects/{project_id}/assembly/artifacts/{artifact_id}`、
    `POST /projects/{project_id}/assembly/artifacts/{artifact_id}/save`、
    `POST /projects/{project_id}/assembly/slices/{slice_id}/seal`。
  - 归一化内容：①按模板口径补/接回**页码页脚**（居中、9pt、单个 `PAGE \* MERGEFORMAT` 域，
    每页都显示；已有含 PAGE 域的页脚则幂等跳过；有页脚部件但引用被删空则把引用接回；无部件则注入）；
    ②清除**大纲级别噪声**（`outlineLvl ≥ 6`，以及题注型段落上的任何大纲级别）；
    ③去掉 `w:pgNumType w:start="0"`，使首页从 1 起。
  - `normalize` 字段示例：`{"is_docx": true, "outline_noise_removed": 306, "created_part":
    "word/footer1.xml", "refs_added": 1, "refs_relinked": 0, "pg_num_start0_removed": 0,
    "sections": 1}`。
  - `POST /projects/{project_id}/assembly/package` 新增两条硬门禁（命中返回 409 并列出文件名）：
    正式 docx **缺页码页脚**、正式 docx **存在大纲级别噪声**。
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/65 ，
    https://github.com/aotocode2026/BidVolt/issues/66

## 2026-09-12（浏览器内 Office 预览）

- **docx→PDF、xlsx→表格预览（discussion #16 T02 / issue #63）**
  - 新增 `GET /files/{file_id}/preview`：预览清单（`kind=pdf|sheet|unsupported`）。
    docx/doc/odt/rtf 返回 `kind=pdf`（元数据含 `page_count/byte_size/cached`）；
    xlsx/xlsm/xltx 返回 `kind=sheet`（`sheets[].cells` 单元格网格，含 `truncated`）；
    旧版 `.xls` 经 LibreOffice 转 xlsx 后同样返回 `kind=sheet`（需服务器安装 `libreoffice-calc`）；
    pdf 返回 `kind=pdf`（原件直出，`converted=false`）；其余格式返回 `kind=unsupported` + `reason`。
  - 新增 `GET /files/{file_id}/preview.pdf`：预览用 PDF 字节（docx 走服务端转换并缓存，pdf 原件直出），
    `Content-Disposition: inline`。
  - 新增 `GET /projects/{project_id}/agent-artifact/{artifact_id}/preview`（可选 `version_no`）与
    `GET /projects/{project_id}/agent-artifact/{artifact_id}/preview.pdf`（同上，作用于成文产物版本）。
  - `GET /files`、`GET /files/{id}/info`、上传响应，以及 `GET /assembly/artifacts`、
    `.../artifacts/{id}/inspect`、`.../artifacts/{id}/versions` 新增 `preview_kind` 字段。
  - 迁移 `0039`：新增 `file_preview` 缓存表（docx→PDF 转换结果按内容寻址缓存，含 RLS）。
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/63

## 2026-09-11（企业资料分类并发）

## 2026-09-11（真实评分类型归一与自动触发）

- **真实评分兼容散乱评分类型并拆解无结构化细则（discussion #59）**
  - `POST /projects/{project_id}/substantive-evaluate` 的评分规则识别不再只认 `score_rule`，
    兼容 `scoring_technical / scoring_business / weight_price / price_rule / scoring / 评分细则 /
    评分规则 / quote_rule`；`structured=null` 的评分类长文本由 LLM 拆项为逐条评分计划；
    `weight_price / price_rule` 作为参考规则以 `verdict=not_applicable` 进入明细，不硬编价格分。
  - `GET /projects/{project_id}/scores` 的 `detail` 新增：
    `weight_config`（商/技/价权重，如 `{"商务":10,"技术":60,"价格":30}`）、
    `reference_rules`（权重/公式说明类规则）、`rules`（本次冻结的逐条评分计划，含
    `rule_id / criterion_id / element / weight / category / revision`）。
  - `GET /projects/{project_id}/scores/{score_id}/items` 中的 `criterion_id` 对拆项规则保持稳定
    （`requirement_id + 子项短哈希`），前端可据此绑定明细与规则。
  - Agent 主会话生成完成（`COMPLETE`）后自动创建 `substantive_evaluate` 任务；
    生成完成即自动评分，评分失败只令评分任务失败，不影响生成任务终态。
  - 关联 discussion：https://github.com/aotocode2026/BidVolt/discussions/59

## 2026-09-10（真实评分闭环）

- **招标实质评分（discussion #53）**
  - 新增 `POST /projects/{project_id}/substantive-evaluate`：发起真实评分异步任务
    （冻结评分细则与正式成果/artifact 版本，LLM 逐条实质评审）。幂等键 = 规则修订 + 成果/artifact 版本；
    能力未就绪（缺标准 / 文件不可读 / LLM 门禁关闭）时任务以 `FAILED_TERMINAL`（`error.code=not_scoreable`）关闭，不回退 builtin。
    响应：`{task_id, status, created, progress}`。
  - 新增 `POST /projects/{project_id}/substantive-items`：Agent（MCP `submit_score_items`）提交真实评分逐条落库。
    请求 `{items: [{requirement_id?, category?, got, full, verdict?, deduction_reason?, risk_level?, suggestion?,
    missing_materials?, rule_source?, response_source?, evidence?, action_type?}]}`；校验 requirement 归属与满分上限，
    逐条回执 `results[]`；相同 payload 幂等（`duplicate=true`）。响应含 `run_id/score_id/snapshot_id/total_score/...`。
  - `GET /projects/{project_id}/scores` 语义变更：只返回最新 `evaluation_type=substantive` 的真实评分；
    无真实评分返回 **404** `detail="暂无真实评分…"`（builtin 完整性检查不再进入评分卡）；响应新增 `evaluation_type`。
  - `GET /projects/{project_id}/scores/{score_id}/items`、`GET /projects/{project_id}/reviews/{run_id}` 新增字段：
    `requirement_id / criterion_id / ruleset_version / verdict / deduction_reason / rule_source / response_source / missing_materials`。
  - `POST /projects/{project_id}/re-evaluate` 语义修正：不再“确认上传建议 + 项目存在任意材料 → 满分”，
    并保留原评分的 `evaluation_type`。
  - MCP `submit_score_items` 契约变更：不再转发 `/evaluate`，改为 `POST /substantive-items` 并实际消费逐条 payload。
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/57

## 2026-09-09（企业资料分类状态）

- **分类中/完成信号**
  - 新增 `GET /enterprise/classification-status`：`{pending, pending_asset_count, running_ingest_count}`；
    `pending=true` 表示本企业存在“待分类资产”或“进行中的入库任务”，前端此时显示“分类中”且不刷新分类数量，
    `pending=false` 后一次性刷新最终数量。
  - `EnterpriseAsset.status` 语义：上传后为 `1`（待分类，分类名称为临时占位），AI 分类完成后为 `2`（待确认），
    人工确认/纠正后为 `3`（已确认）。
  - `POST /enterprise/ingest` 会先落“处理中”标记（`enterprise_ingestion_task.status=1`），完成置 `2`。
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/48

## 2026-09-09（防复发）

- **Agent 主会话中断语义**
  - agent_pipeline 任务被中断/租约回收且未写出终态结论时，任务置为 `CANCELLED`
    （`error.code=interrupted_no_auto_retry`、`progress.status=cancelled/100`），不再自动重跑整条生成；
  - 已写出 `outcome=complete/incomplete` 的任务被回收时仍按结论收尾（DONE / FAILED_TERMINAL）。
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/43

## 2026-09-09（状态一致性）

- **Agent 主会话任务状态一致性**
  - `GET /projects/{project_id}/agent-run/{task_id}` 新增 `retry_count`、`generation`；
    `result` 新增 `attempt`（当前尝试序号），用于区分当前执行与历史结论。
  - 语义调整：`result.outcome=incomplete` 时任务终态为 `FAILED_TERMINAL`
    （`progress.status=failed/100`、`error.code=agent_incomplete`），不再按普通异常重试；
    `outcome=complete` 时为 `DONE`（`progress done/100`）。
  - 普通重试入队时清空上一轮 `error/finished_at`；租约回收对已写出终态结论的主会话任务
    按结论收尾而非重跑。
  - 关联 issue：https://github.com/aotocode2026/BidVolt/issues/42
