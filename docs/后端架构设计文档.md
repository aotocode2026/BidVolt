## 1. 产品定位与后端边界

### 1.1 产品一句话

面向电网、电力设备制造及电力工程企业的投标工作台：以一次投标项目为核心，统一管理企业资料、当前招标材料、商务标/技术标/报价单三份成果、模拟评标、提升建议和历史报价，覆盖从材料上传到成果导出的完整投标流程。

### 1.2 四方分工

| 角色 | 职责 |
|---|---|
| 前端 | 页面展示、类 Word/Excel 在线编辑、选区操作、版本切换、差异呈现、进度与消息展示 |
| **后端业务服务（本团队）** | 认证、数据隔离、项目/资料/成果/版本/评分/报价/审计等业务 API；文件解析与存储；任务编排；导出转换；确定性算法 |
| Hermes Agent | AI 大脑：招标解析、资料匹配、标书生成/校核、模拟评标、针对性修改、对话问答 |
| 独立算法服务 | 历史报价库、单价测算、报价策略（**由本团队以后端模块形式提供**，非第三方） |

### 1.3 必须遵守的产品约束（来自说明书）

1. 一个账号对应一个唯一企业主体，所有数据按企业隔离
2. 当前招标材料为必传项；无已有标书 → 开始生成，有任意已有标书 → 开始校核
3. 资料不足可继续处理，但必须显示缺失项和风险；**禁止模型编造企业事实**
4. 原始上传文件只读保存，AI 修改和用户修改均形成新版本
5. 招标文件解析出的要求优先于系统内置评审规则
6. 每个评分项、风险、提升建议必须能定位到招标要求 / 成果内容 / 企业材料
7. 商务标、技术标、报价单必须保持项目名称、企业主体、金额、工期、参数、数量、报价一致
8. 智能报价只提供建议，用户确认后才能写入报价单
9. 系统不自动登录或提交官方投标平台，最终提交由企业授权人员完成

## 4. 系统模块详设

### 4.1 认证与数据隔离

- **登录**：邮箱 + 密码，注册不发送邮件验证；密码哈希存储（bcrypt/argon2），会话令牌（JWT 或服务端 session）
- **数据库**：生产主库 **PostgreSQL 15+**。技术依据：SaaS/多企业方向下 SQLite 存在硬伤（无 RLS、写并发锁整库、无网络访问、备份恢复弱、无法多实例扩展），而 PostgreSQL 容器化部署成熟，二者不可同日而语。**不以 SQLite 作为生产方案**
- **PostgreSQL 部署（按"服务器本身为容器"的形态设计，架构决策）**：
  - **部署方式：在服务器容器内直接安装 PostgreSQL**（apt/官方二进制，PG 为普通服务进程，无需容器化），**不使用 DinD（容器内嵌套 Docker）跑 PG**——嵌套 Docker 需特权模式，且内层卷落在外层容器可写层，外层容器销毁即丢数据，属反模式
  - **持久化（硬前提）**：PG 数据目录（`/var/lib/postgresql`）指向服务器容器的持久化挂载点（宿主机卷 / named volume）；若环境无持久化能力，必须要求调整部署形态（宿主机直装 PG 或托管 PG），不得以降级数据库换取
  - 备份：每日 `pg_dump` 定时备份 + 备份文件转存对象存储；预留 WAL 归档（PITR）
  - 资源：PG 内存下限约 256MB、磁盘按数据量预留（几百页标书 JSON + 文件元数据，初期数十 GB 足够）
  - 配置：连接串走 Secret Manager；应用连接池（如 pgbouncer，视并发量）
- **隔离（三层纵深）**：
  1. **应用层强制过滤**：所有业务表携带 `enterprise_id`（业务查询中间件强制注入），项目数据再绑定 `project_id`
  2. **数据库 RLS**：核心租户表启用行级安全策略并 `FORCE ROW LEVEL SECURITY`，用 `enterprise_id` 策略限制读写（纵深防御，主防线仍是应用层）
  3. **复合键约束**：租户对象使用 `(enterprise_id, id)` 复合唯一键 + 同租户复合外键，防止跨租户 IDOR
- **对象存储**：租户前缀路径 + 私有桶 + 服务端授权下载（签名 URL）
- **项目级编辑锁**：不支持多用户对同一项目并发编辑。进入编辑加锁、保存释放、超时自动释放；锁冲突提示"他人正在编辑"。为将来协作预留字段，不引入 OT/CRDT

### 4.2 文件服务

- **上传**：支持批量、文件夹、拖拽、压缩包（ZIP/RAR/7Z）；压缩包自动解包（注意 zip 炸弹防护、病毒扫描）
- **格式**：至少 PDF、OFD、DOC、DOCX、XLS、XLSX、CSV、PPT、PPTX、TXT、JPG/JPEG/PNG/BMP/TIFF、ZIP/RAR/7Z
- **存储**：原始文件不可变存储（对象存储/文件系统），AI 和用户修改写新对象（Copy-on-Write）
- **归属（产品决策 D-H）**：数据归属由**上传入口**确定——
  - 企业资料库上传入口 → 企业资料域（enterprise asset，跨项目复用）
  - 项目工作台上传入口 → 当前招标材料域（project material，仅本项目）
  - **禁止**"当前招标材料同时存入企业资料库"选项；项目材料即便包含企业信息也不转存企业资料库
  - 跨域沉淀需另行设计显式、经用户确认的独立流程（本期不做）
- **异常处理**：损坏文件、加密文件、无法解析文件、识别置信度低 → 明确提示用户处理，不静默丢弃
- **文件安全管道（产品决策，P1）**：隔离区 → magic bytes/MIME 校验 → 强制病毒扫描 → 沙箱解析 → 正式入库

### 4.3 文档解析与坐标定位（混合架构）

- **提取层（确定性，用成熟 SDK，不自研）**——文字版文档直接读，不经过视觉模型：
  - 文本类 PDF → PyMuPDF / pdfplumber（有文本层，直接提取）
  - DOCX → python-docx；XLSX → openpyxl
  - OFD → **开源 OFDRW**（已确定采用）提取文本层
- **理解层（LLM/Hermes）**：对提取出的文本/表格做语义识别——判断文件类型（招标公告/技术规范书/评分办法/报价模板…），抽取资格要求、评分细则、否决条款、报价规则等结构化字段
- **视觉模型（qwen-vl）**：仅用于"无文本层"的内容，**不引入传统 OCR**：
  - 扫描版 PDF（纯图片，无文本层）
  - 图片文件（证照、盖章文件、图纸、工程照片）
  - DOCX 内嵌图片（需要理解内容时）
  - 扫描版 OFD
  - qwen-vl 本身同时具备 OCR + 语义理解能力，直接替代 PaddleOCR/Tesseract，无需本地 OCR 服务
- **部署**：qwen-vl 默认走云 API（DashScope），通过 Hermes 配置 `vision_model` 接入，无需本地部署；若后续有数据安全/私有化要求，再评估 vLLM + 开源 VL 模型本地部署
- **坐标体系**：提取层保留"文件 + 页码 + 段落/表格/单元格"索引；LLM/视觉模型抽取结果回写时**必须绑定坐标**，这是"每项识别结果可定位到原文"的技术基础

### 4.4 Hermes Agent 集成

- **部署形态**：独立服务（容器），采用 Python 库嵌入或 API Server（OpenAI 兼容）方式由后端调用；不对前端直接开放
- **调用方式**：后端任务编排模块提交任务 → Hermes 执行 → 回调/SSE 返回白名单事件与结果
- **隔离（产品决策 D-B）**：
  - Profile（每企业一个）+ Session（每项目一个）作为**业务上下文**（记忆隔离、对话隔离）
  - **安全边界不依赖 Profile/Session**，采用**服务端任务级授权上下文**：
    - 每个任务签发一次授权上下文，绑定 `(enterprise_id, project_id, task_id, 允许调用的工具白名单, 对象范围)`
    - Hermes 调用 MCP 工具时，后端按当前任务的授权上下文校验，**禁止长期静态 Token 拥有全部工具和全部对象权限**
    - 企业资料写工具（classify_enterprise_asset/upsert_enterprise_facts）只对"企业资料导入任务"开放；项目材料读取、成果写入、评审提交、网络搜索分别授权
    - 上传文件和网页内容视为**不可信数据**，不能改变工具授权
  - 解析任务使用**无工具、无网络、无长期记忆的隔离模型**
- **并发模型**：任务队列 + 排队；用户处理中补充材料可**插队触发重新规划**（符合说明书"重新评估任务计划"）
- **任务幂等与一致性（产品决策 D-C）**：
  - 任务和所有写工具带 `idempotency_key` + 数据库唯一约束，重复投递不产生重复副作用
  - 版本写入使用 `expected_version_id` CAS，冲突返回 409（防静默覆盖）
  - 任务有重试上限，超过进入**可查询、可人工处理的最终失败状态**（不做独立死信队列）
  - 版本、当前指针、任务结果、审计在**单个事务**中提交（避免"提交成功但任务丢失"）
  - 阻止已取消/已替代/过期任务写入陈旧结果（generation 校验）
- **Skill 清单（初版 5 个）**：
  1. 招标解析——识别材料类型、抽取结构化要求
  2. 资料匹配——招标要求 vs 企业资料库，产出匹配/缺失清单
  3. 标书生成/校核——三份成果生成与一致性检查
  4. 模拟评标——评分细则 + 内置规则组合打分
  5. 针对性修改——按选区产出修改差异
  > 详细设计：SKILL.md 草稿见 `docs/hermes/skills/`，业务 MCP 工具契约见 `docs/hermes/bidvolt-mcp-tools.md`
- **MCP 连接器清单**：业务服务能力（查资料/读材料/写版本/写要求）、报价算法服务、AnySearch 搜索
- **进度与消息（产品决策 D-E，白名单事件，禁止原样透传）**：
  - 后端将 Hermes 输出**过滤后**推送前端，只允许白名单字段：`phase / status / percent / 当前工作 / 面向用户的简短依据或结果摘要 / 必要操作提示`
  - **禁止透传**：原始思维链、工具调用参数、工具原始返回值、内部 ID、凭据、企业资料片段、技术错误栈、安全检测细节、调试信息
  - 发生错误时只显示用户可理解的失败状态和处理建议，详细错误仅进服务端日志和审计

### 4.5 文档结构化模型与版本

- **结构化模型**：docx/xlsx 解析为 JSON 结构（段落、表格、图片、行列、单元格），前端在线编辑的对象是结构化模型而非二进制文件
- **版本链**：每次 AI 修改、用户保存、应用报价策略均形成新版本
  - 保留策略：每类成果保留**最近 20 版** + **里程碑版本永久保留**（原始上传 / AI 生成 / AI 校核 / 用户手动保存）
  - 存储：JSON 内容哈希去重，同内容不重复落盘
  - 恢复粒度：整文件/整版本切换，不做段落级恢复

### 4.6 在线编辑的后端职责

前端主导编辑交互，后端负责：
1. **文档内容服务**：结构化模型（JSON）的读取与保存
2. **版本服务**：保存即新版本（见 4.5）
3. **AI 针对性修改接口**：前端传"选区 + 上下文" → 后端调 Hermes → 返回修改差异 → 前端展示，用户确认后落版本
4. **导出转换服务**：结构化模型 → DOCX/XLSX 文件（后端统一实现，复用于成果下载）

### 4.7 报价能力（确定性算法 + AI 参考建议分层）

- **历史报价（产品决策，外部只读）**：
  - 历史报价数据源位于外部系统，BidVolt 只做**单向查询**，不得新增/修改/删除外部数据
  - 连接账号使用**只读权限**（生产环境禁止写权限）
  - 本地保存本次计算使用的**数据快照**（样本值、来源标识、哈希）用于审计和复算，不回写外部库
- **确定性算法服务**（后端普通模块，非 LLM，纯函数、可单测）：
  - 物料主数据与规格标准化、单位/币种/含税口径统一、异常样本剔除与相似度计算
  - 单价测算：历史中位数、近一年均价、同地区/同规格均价、时间/地区/规格调整、内部成本、最低毛利、投标上限、评分公式
  - 三类策略：中标优先 / 均衡报价 / 利润优先（同一优化问题的三个目标函数，解唯一确定）
  - 输出置信区间、样本快照与算法版本；口径不一致的数据不得参与计算
- **AI 参考建议（产品决策 D-F，保留但限定边界）**：
  - 有明确评分公式 + 样本充分 → **确定性 QuoteEngine 优先**，输出唯一测算价
  - 无公式或样本不足 → AI 可给出**"参考价格区间"**，但：
    1. 不能伪装成确定性测算（前端明确区分"AI 策略建议"与"算法测算价"两个口径）
    2. 必须给出数据来源、判断依据、关键假设、置信度和风险提示
    3. **无可追溯依据时不输出数字**；AI 不得凭空编造成本、最低毛利线或市场数据
  - 数据不足时也可返回"无法可靠测算/需要补充数据"，不得自动退回由 LLM 猜测价格
- **AI 的角色**：AI 通过 MCP 调用 QuoteEngine 取确定值，负责生成推荐理由与依据解释
- **确认门**：报价必须用户确认后写入报价单，形成新版本 + 操作审计（AuditLog）

### 4.8 模拟评标与规则引擎（ReviewProvider 抽象，产品决策 D-G）

- **统一 ReviewProvider 契约**：外部评审机制不能被建模为单一"规则文档"，统一抽象为可插拔 Provider，含版本机制：
  - **Document Provider**：招标材料解析出的评分细则（先解析为版本化规则，交由确定性规则引擎执行）
  - **Code/Rule Provider**：本地内置评审规则（否决风险、完整性、资料有效性、跨文件一致性、方案完整性、内容针对性、报价合理性、格式规范），沙箱隔离执行（无网络、非 root、只读文件系统、CPU/内存/时间限制）
  - **API Provider**：外部评分服务（认证、超时、重试、限流、熔断、幂等），V1 用 Mock Server 契约测试，真实接入留空
- **契约输入**：provider_id/version、project_snapshot_id、三份成果固定 version_id/hash、Requirement 与证据引用、允许发送的数据范围
- **契约输出**：review_run_id、rule/version、score 或风险结论、evidence、suggestion、confidence/unknown、provider 原始响应哈希
- **优先级**：招标要求（Document Provider）优先，内置规则（Code Provider）补充检查
- **数值计算与 LLM 分工**：模拟评标的数值计算（评分公式）进入受限规则 DSL 确定性执行；LLM 只做带证据的事实判断，允许 unknown/abstain；内置检查默认只产生风险，不直接叠加到招标正式总分
- **结果隔离**：外部评审结果不得直接修改成果，必须形成评审记录和建议，由用户或受控流程应用
- **证据链**：每个评分结论关联证据（招标原文坐标 / 成果节点 / 企业材料 revision）＋ 可选搜索来源（带 URL）；证据升级为服务端校验的 EvidenceRef（来源版本、内容哈希、原文范围、exact quote、claim_id）

### 4.9 网络搜索（AnySearch）

- **接入**：通过 **MCP** 接入 AnySearch，作为 Hermes 可选工具；Hermes 原生支持 MCP
- **默认开启**：写标书时按需检索行情 / 竞对 / 政策 / 行业标准，作为内容生产要素（市场分析、政策符合性等章节直接使用）
- **来源分级**：
  | 级别 | 处理 |
  |---|---|
  | 权威来源（政府网站、招标平台、官方公告、国家标准） | 可直接引用进正文，带来源标注 |
  | 一般来源（新闻、行业网站） | 可引用，带来源标注 |
  | 低可信来源（自媒体、论坛、不明页面） | AI 优先不引用，引用时明确提示用户核实 |
- **追溯**：搜索结果统一入库（URL、抓取时间、来源级别），Hermes 引用时结构化记录"哪段内容来自哪个来源"，前端展示出处，用户可点击核实
- **配额与降级**：优先从 Hermes 的 `.env` 读取 AnySearch API Key（注册额度 **每日 1000 次**，永久免费）；读不到则降级为匿名/无 Key 模式（限额较低，约每日 50 次，上线前实测校准）；做调用量配额监控，接近上限时提示或降级
- **边界**：搜索信息可进标书正文与评分依据（定位到来源即可）；招标材料本身仍以用户上传为准（必传项）

### 4.10 导出与终稿检查

- **最小输入快照（产品决策 D-D）**：每次生成、评审、导出记录实际引用的输入版本（不复制整个企业资料库）——
  - 引用的 enterprise asset revision、project material revision、requirement revision、deliverable version
  - 外部历史报价：本次实际采用的样本值、来源标识、哈希
  - 规则、模型、Prompt、Skill、算法版本
  - 最终交付包附**不可变 manifest**（文件哈希、检查结果、豁免、来源版本）
- **一致性校验**：商务标/技术标/报价单的企业名称、项目名称、金额、工期、数量、参数、税率一致
- **检查项**：资质有效期、关键材料缺失、技术参数偏离、报价超限、计算错误、否决风险
- **导出**：商务标 DOCX、技术标 DOCX、报价单 XLSX（**可编辑格式**）＋ 三份成果 PDF（**成品格式**，终稿转换）；另提供模拟评分报告、材料清单、最终交付压缩包

## 5. 关键决策记录（ADR）

| # | 决策 | 结论 |
|---|---|---|
| D1 | Hermes 部署与调用 | 独立服务（Python 库/API Server），后端任务编排调用；不对前端开放 |
| D2 | 租户隔离（架构决策） | PostgreSQL + 应用层强制过滤 + 核心表 RLS 纵深防护 + 复合键约束。技术依据：SQLite 无 RLS/写并发锁库/无网络/备份弱，不适合作 SaaS 主库；PG 在容器形态下可直接安装（apt/二进制，非 DinD），成本可控。**不以单用户为架构前提** |
| D3 | Agent 权限（架构决策） | Profile/Session 仅业务上下文；安全边界用**服务端任务级授权上下文**（enterprise/project/task/工具白名单/对象范围）。成本低（授权对象 + 工具白名单校验），能防"恶意材料诱导 Agent 越权"，接受此方案 |
| D4 | 任务幂等（架构决策） | idempotency_key + DB 唯一约束 + expected_version_id CAS（409）+ 重试上限终态失败；版本/任务/审计单事务提交。均为低成本高价值防御，接受；不引入 Transactional Outbox/fencing token（单队列无竞争场景不需要） |
| D5 | 版本策略 | 最近 20 版 + 里程碑永久保留；JSON 内容哈希去重；整版本级恢复 |
| D6 | 搜索策略 | AnySearch 走 MCP，默认开启，来源分级 + 出处追溯；可进正文与评分依据；配额：读 `.env` 的 Key（1000 次/天），无 Key 降级匿名（约 50 次/天） |
| D7 | 多人编辑 | 暂不支持，项目级编辑锁兜底，预留扩展字段 |
| D8 | 在线编辑边界 | 前端编辑结构化模型；后端管内容 CRUD、版本、AI 修改接口、导出转换 |
| D9 | 进度展示（架构决策） | SSE 白名单事件（phase/status/percent/当前工作/简短依据/操作提示），**禁止透传思维链、工具参数、内部ID、凭据、错误栈**。技术依据：投标业务中工具参数/内部 ID 属无意义噪音且泄露风险高，白名单过滤成本低 |
| D10 | 文档解析选型 | 文字版文档走 SDK（PyMuPDF/python-docx/openpyxl/OFDRW）直接提取；无文本层内容（扫描版 PDF、图片、内嵌图）走 Hermes `vision_model`（qwen-vl 云 API），不引入传统 OCR |
| D11 | 报价展示口径 | 产品 UI 同时展示"测算价"与"AI 建议价"两个口径；AI 建议仅无公式/无数据时触发，须附依据/假设/置信度/风险，无追溯依据不输出数字（产品决策 D-F，架构侧认同：报价属强敏感数字，LLM 直出风险不可控） |
| D12 | 评审机制（架构决策） | 统一 **ReviewProvider** 抽象（Document/Code/API 三类 Provider + 版本机制）；数值计算走受限规则 DSL，LLM 只做带证据的事实判断，允许 unknown/abstain。技术依据：评审来源形态不确定，抽象接口成本低、防未来返工；LLM 只判事实不判数值是防幻觉硬约束 |
| D13 | 材料归属（架构决策） | 归属由上传入口确定，删除"当前招标材料同时存入企业资料库"设计；项目材料不转存企业资料库。技术依据：归属由入口定死可消除数据污染面，避免"项目材料被误当企业资产复用" |
| D14 | 输入快照 | 最小输入快照：记录实际引用的 asset/material/requirement revision + deliverable version + 外部数据样本哈希 + 规则/模型/Skill 版本；交付包带不可变 manifest |

## 6. 非功能需求

- **性能**：标书生成为长任务（分钟级），异步队列 + 进度回报；任务失败可重试、可恢复
- **安全**：文件上传防恶意（隔离区→MIME校验→病毒扫描→沙箱解析）；PostgreSQL RLS + 应用层过滤双保险；Agent 任务级授权；报价写入门户需审计；密钥进 Secret Manager（不由 Agent 读 .env）
- **可追溯**：全链路版本 + 审计 + 最小输入快照 + 引用来源，是"可解释"的技术底座
- **可测试性**：报价算法、ReviewProvider 为确定性模块，单元测试 + 契约测试覆盖；跨租户 IDOR、Prompt Injection、任务幂等测试清单
- **配额与运维**：每租户存储、任务并发、模型 token、搜索、导出配额；RPO/RTO、备份恢复与删除策略
