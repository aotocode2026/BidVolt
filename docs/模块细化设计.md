# 《AI电投助手》后端模块细化设计

> 基于《后端架构设计文档》v0.2（已按 Issue #1 产品决策修订），对 4.1~4.10 各模块逐一细化
> 每个模块输出：接口契约（REST API）、数据表 DDL、核心流程时序、依赖与风险
> 技术栈：后端 **Python 3.11+ / FastAPI / PostgreSQL 15+（含 RLS）**（与 Hermes 及解析 SDK 生态一致）。部署形态：**服务器为单个 Docker 容器**，容器内多进程（ADR D17）——V1 不引入 Redis/独立对象存储服务/独立沙箱容器，任务队列用 PG 任务表，文件存储用本地磁盘适配器（S3/MinIO 适配器保留为多实例形态）。接口契约与 DDL 以 PostgreSQL 为准。
> 部署说明（架构决策，按"服务器本身为容器"形态）：在服务器容器内直接安装 PostgreSQL（apt/官方二进制，PG 为普通服务进程），不使用 DinD 嵌套 Docker；PG 数据目录指向持久化挂载点（宿主机卷/named volume），每日 pg_dump 备份；若环境无持久化能力，调整部署形态（宿主机直装或托管 PG），不降级数据库。

## 4.1 认证与数据隔离

### 4.1.1 接口契约

统一前缀 `/api/v1`，认证接口除外均需携带 `Authorization: Bearer <access_token>`。

| 方法 | 路径 | 说明 | 请求 | 响应 |
|---|---|---|---|---|
| POST | /auth/register | 注册（免邮件验证） | `{email, password, enterprise_name}` | 201 `{user_id, enterprise_id, access_token, refresh_token}` |
| POST | /auth/login | 登录 | `{email, password}` | 200 同上；失败 401 |
| POST | /auth/logout | 登出 | - | 204 |
| GET | /auth/me | 当前用户信息 | - | `{user_id, email, enterprise_id, enterprise_name}` |
| POST | /auth/refresh | 刷新令牌 | `{refresh_token}` | 200 `{access_token, refresh_token}` |
| POST | /projects/{project_id}/edit-lock | 获取项目编辑锁 | - | 200 `{lock_id, expires_at}`；409 已被占用 `{holder, expires_at}` |
| PUT | /projects/{project_id}/edit-lock/heartbeat | 锁心跳续期 | - | 200 `{expires_at}` |
| DELETE | /projects/{project_id}/edit-lock | 释放锁 | - | 204 |

规则：
- 注册即创建企业（一账号一企业），返回 `enterprise_id`，后续所有请求的租户上下文由 token 解析，客户端不需要传 `enterprise_id`
- 编辑锁：进入编辑页获取锁，保存/离开释放，心跳默认 30s，超时 2min 自动释放；同一企业内同一项目仅一个编辑会话
- 密码强度：≥8 位且含字母数字；密码 bcrypt 哈希（cost=12）
- **租户隔离（产品决策 D-A）**：应用层强制过滤（中间件注入 `enterprise_id`）+ 核心租户表 **RLS**（`FORCE ROW LEVEL SECURITY`）+ `(enterprise_id, id)` 复合唯一键 / 同租户复合外键；文件存储适配器租户前缀 + 私有 + 服务端授权下载（V1 本地磁盘，S3 形态语义一致）

### 4.1.3 核心流程时序

```mermaid
sequenceDiagram
    participant U as 前端
    participant API as 后端 API
    participant DB as PostgreSQL
    U->>API: POST /auth/register {email,password,enterprise_name}
    API->>DB: 插入 enterprise + app_user（bcrypt 哈希）
    API->>DB: 签发 access_token(JWT, 含 enterprise_id) + refresh_token
    API-->>U: 201 {access_token, refresh_token, enterprise_id}
    U->>API: 进入编辑页 → POST edit-lock
    API->>DB: 检查锁占用 → 空闲则插入/续期
    API-->>U: 200 {lock_id, expires_at}
    Note over API: 中间件从 JWT 解析 enterprise_id，注入查询上下文<br/>所有 SQL 强制带 enterprise_id 过滤
```

### 4.1.4 依赖与风险

| 项 | 说明 |
|---|---|
| 依赖 | PostgreSQL、JWT 库（python-jose）、bcrypt；编辑锁用表实现（后台任务清理过期锁），不依赖 Redis（ADR D17） |
| 风险 1 | JWT 无状态无法即时吊销 → 登出靠 refresh_token 吊销 + access_token 短时效（默认 2h） |
| 风险 2 | 编辑锁超时释放依赖心跳，网络抖动可能导致误释放 → 心跳窗口放宽（30s 心跳 / 2min 超时） |
| 风险 3 | 密码策略与电网客户安全要求可能不一致 → 预留密码复杂度配置项 |

### 4.1.5 RBAC 与独立权限门禁（产品决策 P1）

权限模型（架构决策 D18）：V1 采用**权限点（permission）+ 用户权限集合**，不做角色表与角色分配 UI（单企业少账号，角色体系是管理成本而非安全收益）；行级隔离仍由 enterprise_id + RLS 承担。

```sql
-- 企业默认权限集（新建企业时初始化）
CREATE TABLE enterprise_permission (
    enterprise_id   BIGINT PRIMARY KEY REFERENCES enterprise(id),
    permissions     JSONB NOT NULL,            -- 权限点数组，见下方枚举
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 用户级覆盖（NULL = 继承企业默认权限集）
ALTER TABLE app_user ADD COLUMN permissions JSONB;
```

**权限点枚举（V1）**：`file.read` `file.download` `file.upload` `project.edit` `deliverable.edit` `deliverable.export` `quote.calculate` `quote.apply` `score.view` `score.confirm` `review_provider.config` `admin.user` `admin.quota` `audit.view`

**独立权限门禁（Issue P1 要求）**：

| 动作 | 必需权限 | 说明 |
|---|---|---|
| 规则修改（启用/禁用/调参 Provider） | `review_provider.config` | 仅管理员；修改写入 review_provider 并记审计 |
| 报价应用（写入报价单） | `quote.apply` | 用户确认 + 权限双门禁，写 AuditLog |
| 终稿导出/交付包 | `deliverable.export` | 导出动作必记审计 |
| 审计查看 | `audit.view` | 审计日志不对普通用户开放 |
| 用户/配额管理 | `admin.user` / `admin.quota` | 仅管理员 |

默认权限集：注册用户的默认权限 = 除 `review_provider.config`、`admin.*`、`audit.view` 外的全部权限点；管理员可增删单个权限点，不引入角色概念。

### 4.1.6 项目 CRUD 与状态机

#### 4.1.6.1 接口契约

| 方法 | 路径 | 说明 | 请求 | 响应 |
|---|---|---|---|---|
| POST | /projects | 创建项目 | `{name, tender_no?, deadline?, note?}` | 201 `{project_id, status}` |
| GET | /projects | 项目列表 | `?status=&page=&size=` | 分页 `{items:[{project_id, name, tender_no, status, deadline, updated_at}], total}` |
| GET | /projects/{project_id} | 项目详情 | - | `{project_id, name, tender_no, deadline, status, materials_summary, deliverables_summary, latest_score_summary}` |
| PATCH | /projects/{project_id} | 更新项目信息 | `{name?, tender_no?, deadline?, note?}` | 200 `{project_id, updated_at}` |
| POST | /projects/{project_id}/archive | 归档（逻辑删除） | - | 204；`is_deleted=true`，归档后只读 |
| PUT | /projects/{project_id}/status | 状态流转 | `{status}` | 200 `{status}` |

规则：
- 创建项目即 `draft`；上传当前招标材料（必传项，产品约束 1.3-2）后流转 `processing`
- `status` 仅允许受控流转：`draft → processing → partial_done → done`，失败/退回走 `draft`；非法流转返回 409
- 归档项目（`is_deleted=true`）只读：不可上传/编辑/提交任务/导出，历史数据保留
- 权限：创建/编辑需 `project.edit`，查看需 `file.read`/`score.view` 默认集

#### 4.1.6.2 数据表 DDL

```sql
CREATE TABLE project (
    id              BIGSERIAL PRIMARY KEY,
    enterprise_id   BIGINT NOT NULL REFERENCES enterprise(id),
    name            VARCHAR(300) NOT NULL,
    tender_no       VARCHAR(100),               -- 招标编号
    deadline        TIMESTAMPTZ,                -- 投标截止
    status          SMALLINT NOT NULL DEFAULT 1, -- 1 草稿 2 处理中 3 部分完成 4 完成
    note            TEXT,
    is_deleted      BOOLEAN NOT NULL DEFAULT FALSE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (enterprise_id, id)                  -- 租户复合唯一键（P0-1）
);
CREATE INDEX idx_project_status ON project(enterprise_id, status) WHERE NOT is_deleted;
```

## 4.2 文件服务

### 4.2.1 接口契约

| 方法 | 路径 | 说明 | 请求 | 响应 |
|---|---|---|---|---|
| POST | /files/upload | 上传文件（批量/拖拽） | `multipart/form-data`：`files[]`、`target`(enterprise/project)、`project_id?` | 201 每文件 `{file_id, name, size, mime, status}` |
| POST | /files/archive | 压缩包解包导入 | `{archive_file_id, target, project_id?}` | 202 `{job_id}` |
| GET | /files/{file_id}/download | 下载原始文件 | - | 200 文件流 |
| GET | /files/{file_id}/info | 文件元信息 | - | `{file_id, name, sha256, size, mime, status, parse_status, category}` |
| GET | /files | 文件列表 | `?target=&project_id=&page=&size=` | 分页列表 |
| DELETE | /files/{file_id} | 删除（仅逻辑删除） | - | 204 |

要点：
- 上传大小限制：单文件默认 200MB（可配）、压缩包解包后**总解压字节上限 2GB**、文件数上限 1000、解压比上限 100:1、嵌套深度 ≤3（zip 炸弹防护）
- **压缩包安全（P1 强制）**：解包时拒绝绝对路径、`..` 路径穿越、符号链接、硬链接、设备文件；任一项命中即整包拒绝并报结构化错误，不部分入库
- **病毒扫描（P1 强制，策略见 ADR D19）**：所有上传文件进入"隔离区 → magic bytes/MIME 校验 → 强制病毒扫描（ClamAV，必装不可选）→ 受限进程解析 → 正式入库"管道；clamd 不可用/超时**阻塞入库（fail-closed）**，不降级跳过
- **病毒库策略（ADR D19）**：镜像构建期打包基线病毒库（保证离线可扫描）；容器启动时 freshclam 增量更新（限时，失败不阻塞启动，记录库版本/时间）；库超 7 天未更新 → 扫描照常执行但标记"库过期"并告警
- 文件归属：`target=enterprise` 存入企业资料域（跨项目复用）；`target=project` 存入项目材料域（仅本项目）。**归属由上传入口确定，无"同时存入企业资料库"选项**（产品决策 D-H；项目材料即便包含企业信息也不转存）
- 上传成功返回后，异步触发解析（见 4.3），`status` 流转：`uploaded → parsing → parsed / parse_failed`

### 4.2.2 数据表 DDL

```sql
CREATE TABLE file_object (
    id              BIGSERIAL PRIMARY KEY,
    enterprise_id   BIGINT NOT NULL REFERENCES enterprise(id),
    project_id      BIGINT,                      -- 归属项目（当前招标材料）；空 = 企业资料库
    owner_type      SMALLINT NOT NULL,           -- 1 企业资料 2 当前招标材料
    bucket          VARCHAR(100) NOT NULL,       -- 存储域（V1 本地适配器 = 租户前缀目录 enterprise_{id}；S3 形态 = 桶名）
    object_key      VARCHAR(500) NOT NULL,       -- 不可变 key：{sha256}/original/{name}（本地适配器 = 相对路径）
    sha256          CHAR(64) NOT NULL,
    original_name   VARCHAR(500) NOT NULL,
    size_bytes      BIGINT NOT NULL,
    mime_type       VARCHAR(100),
    ext             VARCHAR(20),
    category        VARCHAR(50),                 -- 分类（见 4.3 理解层识别结果回填）
    status          SMALLINT NOT NULL DEFAULT 1, -- 1 已上传 2 解析中 3 已解析 4 解析失败 5 需人工处理
    parse_status    JSONB,                       -- {error_code, message, low_confidence_files:[]}
    is_deleted      BOOLEAN NOT NULL DEFAULT FALSE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_file_owner ON file_object(enterprise_id, owner_type, project_id);

CREATE TABLE archive_job (
    id              BIGSERIAL PRIMARY KEY,
    enterprise_id   BIGINT NOT NULL,
    archive_file_id BIGINT NOT NULL REFERENCES file_object(id),
    status          SMALLINT NOT NULL DEFAULT 1, -- 1 解包中 2 完成 3 部分失败 4 失败
    result          JSONB,                       -- {imported:[file_id...], failed:[{name,reason}]}
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 4.2.3 核心流程时序

```mermaid
sequenceDiagram
    participant U as 前端
    participant API as 文件服务
    participant ST as 存储适配器（V1 本地磁盘）
    participant Q as 任务队列
    participant P as 解析服务(4.3)
    U->>API: POST /files/upload（批量）
    API->>OSS: 写入对象（key=sha256/original/name）

    API->>Q: 投递解析任务
    Q->>P: 消费 → 执行解析（见 4.3）
    P-->>API: 回写 parse_status + category
    Note over U,API: 压缩包流程：先上传压缩包 → POST /files/archive<br/>→ 解包 → 逐文件入库（对象复用 sha256 去重）→ 子文件各自触发解析
```

### 4.2.4 依赖与风险

| 项 | 说明 |
|---|---|
| 依赖 | 文件存储适配器（V1 本地磁盘持久卷，租户前缀目录；S3/MinIO 为可选适配器）、任务队列（PostgreSQL 任务表，V1 不引入 Redis，ADR D17）、解压库（pyzipper/patool）、病毒扫描（ClamAV，必装，见上方安全管道） |
| 风险 1 | 大文件上传超时 → 前端分片 + 后端分片合并（v2 再实现，v1 单请求限 200MB） |
| 风险 2 | RAR/7Z 解包库在服务端可用性 → 用 patool 依赖系统解压命令，需容器内置 |
| 风险 3 | 重复文件：同名同 sha256 去重策略需产品确认（"新旧版本"识别依赖此，见说明书企业资料库） |
| 风险 4 | 压缩包内嵌套压缩包 → 限制嵌套深度 ≤3 |
| 风险 5 | 恶意压缩包路径穿越/符号链接 → 解包前逐条校验 entry 路径（拒绝绝对路径、`..`、符号/硬链接、设备文件），命中即整包拒绝 |
| 风险 6 | ClamAV 不可用（未安装/超时）→ 视为安全管道故障，阻塞入库并告警，**不得**降级跳过扫描；病毒库过期（>7 天）→ 扫描照常但标记"库过期"告警（ADR D19） |

### 4.2.5 企业资料域数据模型（Issue 二.3）

企业资料只保存企业长期、可跨项目复用的信息；上传入口为"企业资料库上传入口"。**Agent 只能分类和提取，所有事实必须携带来源文件版本与原文定位；过期、冲突、低置信字段需人工确认。**

```sql
CREATE TABLE enterprise_asset (
    id              BIGSERIAL PRIMARY KEY,
    enterprise_id   BIGINT NOT NULL REFERENCES enterprise(id),
    category_id     BIGINT,                    -- 归档目录（enterprise_asset_category）
    name            VARCHAR(300) NOT NULL,
    asset_type      VARCHAR(50) NOT NULL,       -- 证照/资质/业绩/人员/产品参数/检测报告/财务资料/其他
    source_file_id  BIGINT REFERENCES file_object(id),   -- 原文件（不可变）
    status          SMALLINT NOT NULL DEFAULT 1, -- 1 待分类 2 已分类待确认 3 已确认 4 需人工处理
    is_deleted      BOOLEAN NOT NULL DEFAULT FALSE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ
);
CREATE INDEX idx_ea_owner ON enterprise_asset(enterprise_id, category_id, asset_type);

CREATE TABLE enterprise_asset_revision (        -- 原文件历史版本 + 来源定位（P1 可追溯）
    id              BIGSERIAL PRIMARY KEY,
    asset_id        BIGINT NOT NULL REFERENCES enterprise_asset(id),
    revision_no     INT NOT NULL,
    file_id         BIGINT NOT NULL REFERENCES file_object(id),
    source_location JSONB,                      -- [{file_id,page_no,block_index}] 原文定位
    sha256          CHAR(64) NOT NULL,
    created_by      BIGINT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (asset_id, revision_no)
);

CREATE TABLE enterprise_asset_category (        -- 归档目录（可纠正）
    id              BIGSERIAL PRIMARY KEY,
    enterprise_id   BIGINT NOT NULL REFERENCES enterprise(id),
    parent_id       BIGINT,
    name            VARCHAR(200) NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE enterprise_fact (                  -- 结构化事实（Agent 提取，用户可纠正）
    id              BIGSERIAL PRIMARY KEY,
    enterprise_id   BIGINT NOT NULL REFERENCES enterprise(id),
    asset_id        BIGINT NOT NULL REFERENCES enterprise_asset(id),
    fact_key        VARCHAR(100) NOT NULL,      -- 如 qualification_grade / performance / personnel / product_param
    fact_value      JSONB NOT NULL,             -- 结构化值
    confidence      NUMERIC(4,3),               -- 识别置信度
    status          SMALLINT NOT NULL DEFAULT 1, -- 1 待人工确认 2 已确认 3 已纠正 4 已废弃
    expires_at      TIMESTAMPTZ,                -- 有效期（证照/资质）
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ
);
CREATE INDEX idx_ef_key ON enterprise_fact(enterprise_id, fact_key);

CREATE TABLE enterprise_fact_evidence (         -- 事实 ↔ 来源版本/原文定位 多对多
    id              BIGSERIAL PRIMARY KEY,
    fact_id         BIGINT NOT NULL REFERENCES enterprise_fact(id),
    asset_revision_id BIGINT NOT NULL REFERENCES enterprise_asset_revision(id),
    source_range    JSONB,                      -- {file_id,page_no,block_index,exact_quote}
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

## 4.4 Hermes Agent 集成

### 4.4.1 部署形态与配置

- 与后端**同容器内独立进程**运行（supervisor 管理，ADR D17；平台不支持多容器，单容器为固定形态）。后端以 **Python 库嵌入**为主接入（主进程内嵌或在同一网络内以 API Server 方式），两者对业务透明
- 配置（示例）：

```yaml

  default: deepseek           # 主推理 provider
  dashscope: {}               # 视觉模型 provider（qwen-vl）
models:
  main: deepseek-v4-flash     # 主推理
  vision: qwen-vl-max        # vision_model：扫描件/图片理解
  cheap: deepseek-v4-flash   # 轻量任务（分类/摘要）
mcp_servers:
  bidvolt:                    # 业务服务能力
    command: python
    args: ["-m", "bidvolt_mcp"]
  anysearch:                  # 搜索（key 由 Secret Manager 注入，缺省降级匿名）
    command: python
    args: ["-m", "anysearch_mcp"]
skills:
  enabled: [bidvolt-tender-parse, bidvolt-material-match, bidvolt-bid-generate, bidvolt-mock-evaluate, bidvolt-targeted-edit]
```

- **密钥（P1 强制，与架构第 6 节一致）**：`DASHSCOPE_API_KEY`、`ANYSEARCH_KEY`、各 provider 密钥、`BIDVOLT_INTERNAL_TOKEN` 均由 **Secret Manager 在部署时注入** Hermes 进程环境变量；仓库内不保存 `.env` 明文，Agent 不读取源码目录中的 `.env` 文件。缺 `ANYSEARCH_KEY` 时降级匿名模式（约 50 次/天）
- **深化设计**：业务 MCP 工具契约与 5 个 SKILL.md 草稿见 `docs/hermes/`（README 为总览），Skill 目录结构按 Hermes 官方格式，可直接部署到 Hermes skills 目录

### 4.4.2 隔离模型（产品决策 D-B）

- **Profile = 企业**：每企业一个 Hermes profile，隔离 MEMORY 与技能沉淀（**业务上下文**，非安全边界）
- **Session = 项目**：每项目一个 session，隔离对话上下文（**业务上下文**，非安全边界）
- **任务级授权上下文（安全边界）**：每个任务签发授权上下文，绑定 `(enterprise_id, project_id, task_id, 工具白名单, 对象范围)`；Hermes 调 MCP 工具时后端按授权上下文校验，禁止静态 Token 全权限
- 后端任务编排维护映射：`(enterprise_id, project_id) → (profile, session)`，并向 MCP 会话注入授权上下文

### 4.4.3 任务编排接口与表

| 方法 | 路径 | 说明 |

| POST | /projects/{project_id}/tasks | 提交任务：`{task_type, payload, idempotency_key}`，task_type ∈ `enterprise_ingestion / tender_parse / material_match / bid_generate / bid_review / mock_evaluate / targeted_edit / chat`（`enterprise_ingestion` 为企业资料导入任务，是 classify/upsert 企业资料写工具的唯一授权入口） |
| GET | /tasks/{task_id} | 任务状态与结果 |

```sql
CREATE TABLE task (
    id                BIGSERIAL PRIMARY KEY,
    enterprise_id     BIGINT NOT NULL,
    project_id        BIGINT NOT NULL,
    task_type         VARCHAR(50) NOT NULL,
    idempotency_key   VARCHAR(100) NOT NULL,      -- 幂等（产品决策 D-C）
    priority          SMALLINT NOT NULL DEFAULT 5, -- 补充材料插队任务 = 1
    status            SMALLINT NOT NULL DEFAULT 1, -- 1 排队 2 执行中 3 完成 4 失败(可重试) 5 已取消 6 终态失败(重试耗尽)
    payload           JSONB NOT NULL,
    result            JSONB,                       -- 完成结果（含文档写入请求）
    progress          JSONB,                       -- {phase, status, percent, current_work}（白名单）
    retry_count       SMALLINT NOT NULL DEFAULT 0,
    generation        INT NOT NULL DEFAULT 1,      -- 陈旧写入拦截（产品决策 D-C）
    error             JSONB,

    finished_at       TIMESTAMPTZ,
```

### 4.4.6 任务状态机与幂等语义

```mermaid
stateDiagram-v2
    [*] --> queued: 提交任务（idempotency_key 唯一）
    queued --> running: worker SKIP LOCKED 领取
    running --> done: 成功（结果+版本+审计单事务提交）
    running --> retrying: 可重试失败
    retrying --> running: 重试（retry_count+1）
    retrying --> failed_terminal: 重试耗尽（终态失败，可人工处理）
    queued --> cancelled: 用户取消/超时
    running --> interrupted: 补充材料插队（追加指令，不取消）
    interrupted --> running: 同 session 继续执行
    running --> requeued: worker 崩溃/lease 过期
    requeued --> running
```

规则（产品决策 D-C + P0-4）：

| 场景 | 行为 |
|---|---|
| 重复投递（同 `idempotency_key`） | 命中 `UNIQUE(idempotency_key, enterprise_id)`，返回**原 task_id + 当前状态**，不产生新任务/副作用 |
| 重试 | `retry_count+1`；可重试错误（Provider 超时/网络抖动/worker 崩溃）自动重试，上限默认 3 次 |
| 重试耗尽 | `status=6 终态失败`，`error` 可查，支持人工重投（新 idempotency_key） |
| 陈旧写入 | `generation` 校验：任务被取消/替代/过期后调用写工具返回 409；版本写入走 `expected_version_id` CAS |
| 打断/插队 | 补充材料 → `POST /tasks/{id}/interrupt`：执行中任务追加指令消息（同 session），不强制取消；新建插队任务 `priority=1` |
| worker 崩溃恢复 | `running` 且 lease 过期（默认 5min 心跳）→ 回 `queued` 并 `retry_count+1`；单实例下 lease 心跳由 worker 自身维护 |
| 提交一致性 | 版本、当前指针、任务结果、审计在**单个事务**提交；队列消费用 `SELECT … FOR UPDATE SKIP LOCKED` |

## 4.5 文档结构化模型与版本

### 4.5.1 结构化模型定义

- 商务标/技术标：`DocModel` JSON —— 段落、标题、表格、图片节点的有序数组（docx 解析产物）

### 4.5.4 版本保留与去重规则

- 保留：非里程碑版本仅保留**最近 20 版**（按版本号倒序），超出即软删（`is_deleted` 标记，可配置保留数）
- 里程碑（永久）：`version_type ∈ {1 原始上传, 2 AI生成, 3 AI校核}` 且用户手动保存标记的版本
- 去重：写入时计算 `content_hash`，与既有版本相同则复用同一 `content_json`（不重复落盘），`content_hash` 加索引

## 4.7 报价能力（确定性算法 + AI 参考建议分层，产品决策 D-F）

### 4.7.1 模块边界

- **历史报价（外部只读 Provider，Issue 三.D 契约）**：只暴露三类查询能力——`query_history`（历史中标查询）、`get_material_samples`（物料样本明细）、`get_source_metadata`（来源元数据）；连接账号只读（生产禁止写）；本地保存本次计算的数据快照（样本值/来源/哈希）用于审计复算，不回写外部库

### 4.7.4 算法说明（确定性核心）

- 预处理：物料主数据标准化、单位/币种/含税口径统一、异常样本剔除与相似度计算；**口径不一致的数据不得参与计算**
- 测算：`建议价 = 基准价 × (1 + Σ调整系数)`；基准价 = 历史中位数（默认）或近一年/同地区/同规格均价（可切换）
- 三类策略（同一优化问题的三个目标函数，约束求解唯一解）：
  - **win 中标优先**：`score_formula(price)` 最大，约束 `(price - cost)/price ≥ min_profit_rate` 且 `price ≤ cap`
  - **balance 均衡**：评分与毛利率加权 `α·score + β·margin` 最大
  - **profit 利润优先**：`margin` 最大，约束 `score ≥ score_floor` 且 `price ≤ cap`
- 全部为纯函数（输入确定 → 输出确定），单元测试覆盖：公式正确性、边界（成本>上限、无历史数据、口径不一致拦截）

### 4.8.1 统一 ReviewProvider 契约

### 4.8.5 证据与分工规则（产品决策 D-G + D-J）

- **EvidenceRef（服务端校验）**：`{source_version_id, content_hash, source_range(文件/页码/块), exact_quote, claim_id}`；服务端生成并校验，LLM 不能自造证据
- **数值 vs 语义分工**：评分公式数值计算进入**受限规则 DSL** 确定性执行；LLM 只做带证据的事实判断，允许 unknown/abstain
- **结果隔离**：外部评审结果不得直接修改成果，必须形成 review_run + review_item 记录和建议，由用户确认后触发受控流程应用
- **内置检查**：默认只产生风险提示，不直接叠加到招标正式总分
- **"一键提升"语义**：触发材料上传→确认→重审的五步工作流，不是直接修改分数。确认前的分数只标记为"预估"（review_item.improvable），重审后才成为实际得分（新 review_item.got）
- **批量操作**：返回逐条结果（succeeded/conflict/skipped + reason），不做"批量成功/失败"的粗粒度返回

### 4.8.6 依赖与风险

| 项 | 说明 |
|---|---|
| 依赖 | 4.3 requirement（评分细则→Document Provider）、4.10 snapshot、4.5 成果版本、沙箱执行环境、Hermes 事实判断 |
| 风险 1 | 评分公式千差万别 → 确定性部分按 requirement.score_rule 的 structured 参数驱动 DSL，未识别出公式的项走 Hermes 语义评估并标 unknown/参考 |
| 风险 2 | 证据定位要求高 → review_item.evidence 必须为服务端生成的 EvidenceRef（缺证据的评分项不计入可解释总分），不满足则提示 |
| 风险 3 | API Provider 不可用（超时/失败/非法数据）→ 熔断降级为仅 Document+Code Provider，且不污染成果与评分主记录 |
| 风险 4 | Code Provider 逃逸 → 受限进程沙箱（单容器唯一形态，ADR D17）：非 root + rlimit + 只读输入目录；契约测试验证边界；强隔离需多容器，平台不支持，列为演进预留 |
| 风险 5 | 提升闭环状态一致性 → review_item.status 状态机（pending_confirm → confirmed/rejected → re_reviewed），幂等 + CAS 防并发覆盖；批量操作中某条失败不影响其他 |
| 风险 6 | 多条 AI 修改同一成果合并冲突 → 后端合并校验后生成一个 deliverable_version，CAS 冲突返回 409 不静默覆盖 |

## 4.9 网络搜索（AnySearch）

### 4.9.1 接入方式与触发

- **接入**：AnySearch 通过 MCP server 挂到 Hermes（配置见 4.4.1），Hermes 写标书/回答行情类问题时按需调用
- **默认开启（P1 门禁前置）**：功能默认开启，Agent 自主决定何时搜索；但生产上线前必须完成**数据分级与客户授权确认**（架构第 7 节待确认问题 #2），未确认前按 P1 门禁**默认关闭**，确认后按配置开启
- **出站安全（P0-2，架构落地）**：搜索出网做**应用层 DLP 脱敏 + 域名白名单**（手机号、身份证、银行账号、统一社会信用代码等正则脱敏后转发；仅允许 AnySearch 等白名单域名），若部署环境提供 `HTTP_PROXY` 则经代理出网，否则直连白名单域名；脱敏与域名策略为代码内强制逻辑，不依赖外部代理设施
- **配额策略**：优先读取 Secret Manager 注入 Hermes 环境的 `ANYSEARCH_KEY`（注册额度 1000 次/天）；缺省降级匿名模式（约 50 次/天，上线实测校准）；后端统计每日调用量，接近 80% 上限时告警

### 4.11.2 备份、恢复与删除策略

- **备份**：容器内 cron 每日 `pg_dump` 到持久卷 `/var/lib/bidvolt/backups`（保留 30 天）+ 可选 rclone 转存外部对象存储；`archive_mode=on` 归档 WAL（PITR 预留）
- **RPO/RTO**：RPO ≤ 24h（每日备份），RTO ≤ 4h（备份恢复 + 服务重建）
- **恢复演练**：上线前与每季度做一次恢复演练，验证备份可还原、快照可复算
- **删除策略**：

  - 导出产物：默认 7 天后清理（4.10.5 风险 2）
  - 审计日志：默认保留 180 天（可配），到期归档后删除

### D.2 RLS 策略清单（P0-1）

- 启用对象：`enterprise`、`app_user`、`refresh_token`、`file_object`、`project`、`task`、`requirement`、`requirement_revision`、`deliverable`、`deliverable_version`、`review_run`、`score_record`、`review_item`、`review_material_link`、`quote_calc`、`search_source`、`citation`、`audit_log`、`enterprise_asset`、`enterprise_fact`、`project_material`、`project_snapshot` 等全部业务表
- 每表执行：`ALTER TABLE … ENABLE ROW LEVEL SECURITY; ALTER TABLE … FORCE ROW LEVEL SECURITY;`
- 统一策略：`CREATE POLICY tenant_isolation ON <表> USING (enterprise_id = current_setting('app.enterprise_id')::bigint) WITH CHECK (enterprise_id = current_setting('app.enterprise_id')::bigint);`
- 注入方式：应用中间件在**每个事务内** `SET LOCAL app.enterprise_id = <id>`（连接池安全，不污染复用连接）；无该设置的事务默认拒绝（`current_setting` 为 NULL 时策略不匹配）
- 例外表：`review_provider`（全局配置，无 enterprise_id，用应用层只读权限控制）、`enterprise_asset_category` 等纯租户目录表同样启用
- 复合键：租户对象一律 `UNIQUE (enterprise_id, id)`，同租户复合外键（如 `(enterprise_id, project_id)` 引用 project）

### D.3 迁移顺序建议

1. **M1 基础**：enterprise / app_user / refresh_token / enterprise_permission / project / project_edit_lock / tenant_quota / audit_log / file_object / archive_job
2. **数据域**：enterprise_asset 系 / project_material 系 / doc_block / requirement 系 / deliverable 系 / task
3. **业务域**：quote_calc / history_price_snapshot / review_provider / review_run / score_record / review_item / review_material_link / search_source / citation / final_check / export_job
4. **RLS**：全部表启用 FORCE RLS + 统一策略（D.2），随后跑 A-1 跨租户用例组
