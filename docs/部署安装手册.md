# 部署安装手册（容器直接安装版）

> 服务器容器是**现成提供**的（不需要镜像构建）。本手册覆盖：本地记录连接信息 → 推送代码 → 容器内一键安装 → 验证 → 日常运维。
> 安全红线：`local/container.env` 与 `.env` **禁止上传 git**（已由根目录 `.gitignore` 排除）；密钥只进 Secret Manager 或容器环境变量。

---

## 1. 前置信息（拿到容器后填写）

把容器 IP、用户名、密码填入本地 `local/container.env`：

```ini
CONTAINER_HOST=<容器 IP>
CONTAINER_USER=<登录用户名>
CONTAINER_PASSWORD=<登录密码>
CONTAINER_SSH_PORT=22
CONTAINER_REPO_PATH=/data/bidvolt
```

## 2. 本地准备

1. 复制 `.env.example` 为 `.env`，填入真实值：
   - `APP_DB_PASSWORD` / `DATABASE_URL`（数据库密码）
   - `JWT_SECRET`（>=32 位随机串）
   - `BIDVOLT_INTERNAL_TOKEN`（MCP 内部认证）
   - `DASHSCOPE_API_KEY` / `ANYSEARCH_KEY`（云模型/搜索；`DATA_CLASSIFICATION_CONFIRMED=0` 时保持关闭）
2. 提交并推送代码（`.env`、`local/` 已被 gitignore，不会误传）。

## 3. 连接与部署

```bash
# 本地：复制仓库与 .env 到容器（代码真源 = /data/bidvolt，路径由 REPO 变量配置，不依赖符号链接）
scp -r -P <port> . <user>@<host>:/data/bidvolt
scp -P <port> .env <user>@<host>:/data/bidvolt/.env

# 容器内：一键安装（apt 系统包 + Python venv + requirements + 初始化 PG/迁移 + 启动 supervisor）
ssh -p <port> <user>@<host>
cd /data/bidvolt
bash deploy/install.sh
```

`install.sh` 自动完成：
1. apt 安装 PostgreSQL / ClamAV / LibreOffice / supervisor / cron / rclone 等
2. 创建 `.venv` 并 `pip install -r requirements.txt`（+ requirements-dev.txt）
3. 在 `/data`（平台外挂持久卷）内准备子目录 `pgdata/appdata/backups`（卷本身由平台挂载，无需自建）
4. 用 `REPO`/`HERMES_HOME` 变量生成 supervisor 配置与运维脚本（路径写死在生成结果中）
5. 初始化 PG 集群（空数据卷时）→ 建库/用户 → alembic 迁移 → 启动全部服务
6. 安装 Hermes Agent（数据/venv 位于 /data/hermes，`SKIP_HERMES=1` 可跳过）

> 路径配置：`REPO=${REPO:-/data/bidvolt}`、`HERMES_HOME=${HERMES_HOME:-/data/hermes}`；
> `deploy/supervisord.conf` 里的 `__REPO__`/`__HERMES_HOME__` 由 install.sh 替换。

## 4. 验证

```bash
# 容器内
bash /usr/local/bin/bidvolt-healthcheck   # 退出码 0 = PG + API 健康
curl http://127.0.0.1:8123/healthz        # 期望 {"status":"ok"}
supervisorctl status                      # postgres/app/worker/hermes/clamd/backup-cron 应全部 RUNNING
tail -f /var/log/bidvolt/supervisord.log
```

## 5. 日常运维

- **重启服务**：`supervisorctl restart app`（单模块）；`supervisorctl reload`（改配置后）
- **备份**：每日 02:00 cron 自动 `pg_dump` 到 `/data/backups`（保留 30 天，`/etc/cron.d/bidvolt-backup` 必须带 `root` 用户字段，否则 cron 静默忽略；恢复用 `pg_restore`）
- **日志**：`/var/log/bidvolt/`（supervisord / backup / app 输出）
- **升级代码**：容器内 `git pull && .venv/bin/pip install -r requirements.txt && supervisorctl restart all`
- **容器重启后自动恢复**：容器入口为 sshd（无 systemd），`install.sh` 会安装 `/etc/ssh/sshrc`
  兜底——SSH 登录时若 supervisord 未运行则自动 `nohup /usr/local/bin/bidvolt-init` 拉起全部服务。
- **修改云能力开关**：`DATA_CLASSIFICATION_CONFIRMED` / `CLOUD_LLM_ENABLED` / `SEARCH_ENABLED` 等修改的是
  `/data/bidvolt/.env`，但运行中的 supervisor 继承容器启动时的旧环境变量（环境变量优先级高于 .env），
  仅 `supervisorctl restart app` 不会生效。正确做法二选一：
  1. 重启整个容器（推荐，入口脚本会重新 source .env）；
  2. 把开关固定进 `/etc/supervisor/conf.d/bidvolt.conf` 的 `[program:app]/[program:worker]`
     `environment=` 后执行 `supervisorctl update app worker && supervisorctl restart app worker`
     （本次开发容器已按此方式固定为解锁状态）。
- **数据安全**：`/data` 为平台外挂持久卷（约定），容器重建后数据仍在；`/data/pgdata`、`/data/appdata`、`/data/backups` 是唯一需要保留的目录

## 6. 安全说明

- `local/container.env`（容器连接信息）与 `.env`（API key/密码）**绝不提交 git**，由根目录 `.gitignore` 兜底
- 容器内的 `.env` 权限收紧：`chmod 600 /opt/bidvolt/.env`
- 云模型/搜索受 `DATA_CLASSIFICATION_CONFIRMED` 门禁控制（见 `.env.example` 与 `docs/数据分级与授权确认清单.md`）

### AnySearch 接入说明（运维）

- 官方端点：`https://api.anysearch.com/mcp`（JSON-RPC 2.0 `tools/call`，工具 `search`），
  `ANYSEARCH_BASE_URL` 缺省即此值；开发/测试默认 `SEARCH_MODE=anysearch`。
- 未配置 `ANYSEARCH_KEY` 时走匿名额度（约 50 次/天，仅限测试/冒烟；开发期已启用）；
- 正式使用：注册 AnySearch 获取 Key（默认 1000 次/天），写入 Secret Manager 的 `ANYSEARCH_KEY`，
  并将 `SEARCH_ENABLED=1`（生产需数据分级清单 A2 签署）；有 Key 时请求带 `Authorization: Bearer <key>`，
  无 Key 时匿名调用（保留 `X-Anysearch-Client: mcp/1.0.0` 头）。
- 出站请求强制经过 DLP 脱敏（手机号/证件号/银行卡/信用代码）与域名白名单（`app/services/search_service.py`）；
- 结果按 `trust_level` 分级（gov.cn 等官方域为 L1），匿名额度耗尽返回可读错误并建议配置 Key；
- 可配置 `HTTP_PROXY` 让搜索请求走代理（`settings.http_proxy` 或环境变量）。
- 已验证：匿名模式已连官方端点实测通过（返回真实中文搜索结果），真实链路冒烟见 `scripts/smoke_cloud_live.py`。
- 连接容器尽量用 SSH key 替代密码；密码方案下注意传输通道安全（本手册 scp 走 SSH）

## 7. 数据与持久化（/data 约定）

平台约定 `/data` 为容器外挂持久卷（本容器实际挂载自宿主机磁盘，容器重建不丢）。**业务数据一律放 /data**：

| 路径 | 内容 | 是否持久 |
|---|---|---|
| `/data/pgdata` | PostgreSQL 数据目录（RLS、企业/项目/成果/审计等全部业务表） | 是 |
| `/data/appdata` | 上传文件/成果文件（按 enterprise_id 租户前缀目录） | 是 |
| `/data/backups` | 每日 `pg_dump`（保留 30 天）+ WAL 归档（PITR） | 是 |
| `/data/logs/bidvolt` | supervisord/backup 等运行日志（`/var/log/bidvolt` 为符号链接） | 是 |
| `/data/bidvolt` | 代码 + Python venv（`/opt/bidvolt` 不再使用） | 是 |
| `/etc/supervisor`、`/etc/bidvolt`、`/etc/clamav` | 配置（由部署脚本生成，重建后可恢复） | 否 |

重建容器后的恢复步骤：重装系统包 → 复制代码 → 建 venv → 恢复 `.env`（Secret Manager）→ 运行
`bash /data/bidvolt/deploy/install.sh`（检测到 `/data/pgdata/PG_VERSION` 已存在会跳过 initdb，直接迁移+启动）→
必要时 `pg_restore` 最近 dump 校验数据。

## 8. Hermes Agent（已部署）

- 位置：`/data/hermes`（venv + 数据 + skills，重建容器后仍在；重装脚本 `deploy/install-hermes.sh` 幂等）
- 守护：supervisor `[program:hermes]` → `hermes serve --skip-build --host 127.0.0.1 --port 9119`
- 模型：主推理 MiniMax-Text-01（minimax provider，max_tokens=8000）；
  视觉辅助 = 百炼 qwen-vl-max（`auxiliary.vision` custom，DashScope 兼容端点）
- MCP：`bidvolt`（stdio，24 工具）；调用后端需 `BIDVOLT_INTERNAL_TOKEN`
  （当前为 Hermes 服务账号 JWT，见 `scripts/` 说明；生产按 P0-2 走任务级 capability token）
- Skills：`bidvolt-*` 5 个（`/data/hermes/skills/bidvolt/`）
- 验证：`hermes skills list`、`hermes mcp list`、`hermes -z '<提示词>' --yolo --cli`
